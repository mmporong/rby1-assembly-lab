# RJ45 G2 축별 손실 스케일링 진단

한 개의 고정된 시연 궤적에서 BC 정책의 6축 출력 오차를 같은 비중으로 학습시키면, 단순 MSE보다 상태에 따른 수정량을 더 잘 맞추는지 확인했다. 입력 395행, 모델 초기값, 난수 상태, Adam 설정, 학습률 `1e-3`, 2,000회 업데이트는 두 조건에서 같게 유지했다.

## 비교 조건

- R0: 6축 원래 명령 좌표의 MSE
- R1: 각 축 오차를 시연 데이터의 축별 표준편차로 나눈 뒤 계산한 MSE
- 추론 출력: 학습 후에도 별도 역스케일링이나 클리핑 없이 원래 6D 정규화 명령 좌표를 사용
- 기준선: 각 축의 학습 데이터 평균값을 모든 시점에 출력하는 상수 정책

축별 표준편차는 395행에서 `float64`, `ddof=0`으로 계산했다. 평가에는 이 값을 유지하고, 학습 손실 텐서에만 `float32`로 변환했다. 6축 모두 `1e-8` 하한보다 커서 하한 처리는 발생하지 않았다.

## 결과

| 지표 | R0 원래 MSE | R1 축별 스케일링 | 사전 기준 |
| --- | ---: | ---: | ---: |
| 원래 6D 명령 MSE | 2.320454e-6 | 2.161193e-6 | R1 < R0 |
| 상수 정책 대비 MSE 비율 | 0.98564 | 0.91799 | R1 ≤ 0.90 |
| 축 균형 MSE | 0.98950 | 0.92982 | R1 ≤ 0.90 |
| 모든 축의 상수 정책 대비 비율 | 통과 | 통과 | 각 축 ≤ 1.10 |

R1은 R0보다 원래 명령 MSE가 약 6.9% 낮았고, 6개 축 모두 상수 정책보다 악화되지 않았다. 다만 상수 정책 대비 비율과 축 균형 MSE가 각각 `0.91799`, `0.92982`로 사전에 고정한 `0.90` 기준에 미치지 못했다. 따라서 최종 판정은 **FAIL**이다.

R0는 이전 진단의 초기 정책 상태 해시, 최종 정책 상태 해시, 최종 MSE를 모두 재현했다. R0와 R1은 같은 초기 정책 상태와 같은 난수 상태에서 시작했다.

## 재실행 기록

첫 실행에서도 R1의 상수 정책 대비 비율은 `0.91799`, 축 균형 MSE는 `0.92982`였으며 최종 판정은 FAIL이었다. 검토 과정에서 평가용 표준편차가 `float32`로 변환되어 상수 기준선의 축 균형 MSE가 `0.9999999896`으로 계산된 점을 발견했다. 판정 기준, 시드, 업데이트 횟수, 학습률은 유지하고 평가용 표준편차만 원래 `float64` 정밀도로 보존해 다시 실행했다. 최종 상수 기준선은 정확히 `1.0`이며, R1의 핵심 수치와 판정은 바뀌지 않았다.

초기 중단본과 검토 전 성공본은 `artifacts/cloud/rj45-resume-20261030/` 아래 ignored 증거 폴더에 코드·프로토콜·결과·체크포인트·해시 기록과 함께 보존했다. 초기 중단본의 복구 코드 SHA-256은 당시 프로토콜에 고정된 `a2488663…`과 일치하며, 원자적 공개 전에 중단되어 결과 파일과 체크포인트는 생성되지 않았다.

## 해석 범위

이 결과는 같은 시연 궤적을 반복 학습한 오프라인 회귀 진단이다. 축별 손실 스케일링이 단순 MSE보다 나은 방향을 보였지만, 상태 피드백 학습, 물리 시뮬레이션의 폐루프 삽입 성공, PPO의 기여, 새로운 조건에서의 일반화는 아직 입증하지 못했다. 두 체크포인트의 artifact kind는 `diagnostic_not_main_bc`이며 본실험 초기화에 사용하지 않는다.

정본 수치는 [result.json](result.json), 실행 전 고정 계약은 [protocol.json](protocol.json)에 있다.
