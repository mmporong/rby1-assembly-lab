# RJ45 게시용 영상의 가시성 수정 · 2026-11-01

책상을 짙은 회색으로 바꾸고 조명·노출을 낮췄다. 오른팔이 연결부를 가리지 않는 측면 카메라로 기존 fresh-05 비교를 재생하고, 연결부 주변을 확대했다. 하늘색 부품은 RJ45 플러그, 흰색 외함은 LAN 어댑터다.

- [비교 영상](../../media/rj45/publication-20261101/comparison.mp4): 1920×1080, 60 fps, 1,574 frames, 26.233초
- [미리보기](../../media/rj45/publication-20261101/preview.png)
- [원평가 자료](../rj45-multibias-20261031/README.md): 새 오차 8조건에서 single64 2/8, multi64 3/8, zero 2/8

| 이번 시각 재생 | 판정 | 종료 횡오차 | 삽입 깊이 |
|---|---|---:|---:|
| multi64 PPO | valid_success | 33.509179 µm | 12.264989 mm |
| 학습 보정 없음 | valid_failure / episode_timeout | 64.711639 µm | 12.221241 mm |

두 실행은 원평가 fresh-05의 초기 79차원 관측 해시와 판정이 일치했다. 새 학습이나 평가 통계 갱신은 하지 않았다. 성공은 프로젝트의 깊이·횡오차·유지 시간·파지·하중·속도 등 기준을 충족했다는 뜻이며, 실물 성능이나 Ethernet 연결을 의미하지 않는다. 원평가의 효과·일반화·최종 정책 입증 주장은 계속 false다.

카메라 eye는 (0.75, -0.0655, 1.1205) m, target은 (0.37, 0.0145, 0.9005) m다. 1280×960 원본에서 (x=384, y=288, width=512, height=384)를 잘라 각 패널로 확대했다. 시간 보간이나 로봇 프레임 반복은 없다. 종료한 패널은 결과 카드로 바뀌며 마지막 2초는 정지 결과 카드다.

기존 촬영물과 원평가 자료는 보존했다. a~e 시도의 운영 오류·카메라 선택 이유는 `retake-history.json`, 원시 파일의 보관·해시는 `recovery.json`, 최종 합성은 `comparison-provenance.json`에 기록했다. 카메라 선택은 d 미리보기의 가시성 검수에 따랐으며 e 결과를 보고 정책·오차·물리·판정 기준을 바꾸지 않았다.

Isaac 앱 종료 시 Python 후처리가 실행되지 않는 경우에는 외부 실행기의 실제 native exit=0과 봉인 보고서·영상·미리보기 SHA를 검증해 완료를 확정했다. `app_close_exit_code`를 임의로 0으로 채우지 않고 native witness를 별도로 남겼다.
