# 휴대형 LAN 어댑터의 RJ45 양팔 삽입

왼손은 작은 LAN 어댑터를 들고 지지하고, 오른손은 RJ45 플러그를 잡아 포트에 삽입한다. 지지물이 고정되지 않아 한 손의 움직임이 다른 손의 정렬 오차에 영향을 주는 과제다. 먼저 기본 그리퍼의 마찰 파지와 기계적 삽입을 확인하고, 이후 잔차 강화학습이 기준 제어보다 접촉 오차를 얼마나 줄이는지 비교한다.

## 구현 범위

- 로봇: 공식 RB-Y1 M과 기본 RB gripper. 손가락을 줄이거나 커넥터를 확대하지 않는다.
- 잭: TE 5555153-1의 공식 STEP을 시각 형상으로 사용한다. 삽입 공동은 테이퍼 입구·측면·상하·뒷벽으로 나눈 복합 충돌 형상으로 구성한다.
- 플러그: TE 도면 C-558530 revision H의 최대 외형 치수로 만든 모델이다. 공급사 STEP으로 표시하지 않는다. 폭 11.79 mm, 전체 길이 22.74 mm, 압착된 전면 높이 6.15 mm를 적용한다.
- 어댑터 외함: 잭을 넣은 32×66×22 mm의 설계 형상이다. 시판 완제품의 CAD나 분해 모델은 아니다.
- 픽업 지그: 45도 사선 파지에서 손가락과 테이블이 간섭하지 않도록 만든 위가 열린 로케이터다. 2 mm 상판, 좌우 레일, 전면 스토퍼로 구성하며 플러그와 측면·전면 사이의 초기 틈은 각각 0.15 mm다. 초기 미끄러짐과 회전은 줄이지만 위로 들어 올리는 방향은 열려 있다. 고정 조인트는 사용하지 않는다.
- 질량 55 g·4 g, 마찰·힘 한계는 시뮬레이션 가정이다. 제조사 실측값이나 하드웨어 교정값으로 주장하지 않는다.

플러그와 잭이 모두 8P8C 외형을 사용하지만, 이 모델 조합을 공급사가 인증한 mating pair로 주장하지 않는다. 잭 측면의 모델상 폭은 11.9126 mm이며, 최대 폭 플러그와의 편측 틈은 약 0.0613 mm다. 접촉 offset은 0.020 mm로 설정한다. 원본 도면의 공차와 접점 스프링은 별도의 물성 모델이 없으므로, 이 값으로 실제 삽입력을 예측하지 않는다.

잠금 탭은 눌린 상태의 시각 형상이고 케이블은 짧은 시각 형상이다. 탭 잠금·유지력, 케이블 굽힘과 장력, 전기 접점 및 Ethernet 연결은 검증하지 않는다.

## 동작과 판정

1. 기본 자세에서 팔의 경유 자세를 거친 뒤 몸통을 낮추고, 두 부품의 파지 위치로 접근한다.
2. 양 손가락의 대상 물체 접촉과 실제 리프트를 확인한다.
3. 왼손이 든 잭의 입구 좌표계에 오른손 플러그 끝을 맞춘다.
4. 느린 삽입 명령과 하중 제한을 적용한다. 접촉으로 막히면 기준 제어의 후퇴·재정렬 단계를 사용한다.
5. 파지를 유지하며 깊이·횡오차·각도·하중·상대속도 조건을 연속 유지해야 성공으로 판정한다.

손가락을 닫는 `CLOSE`와 15 mm 리프트를 확인하는 `CHECK_LIFT` 구간에서는 단계 진입 시점의 양손 파지 자세를 월드 좌표계에 고정해 목표로 쓴다. 물체 자세를 계속 따라가는 목표가 파지 오차를 가리는 일을 막기 위한 제어 기준이며, 물체 자세나 힘을 덮어쓰지는 않는다.

설정의 길이는 m, 각도는 rad다. 입구·플러그 끝·양쪽 파지점을 위치와 quaternion으로 정의한다. 기록한 두 물체의 원시 자세를 NumPy로 다시 계산해 런타임 삽입 깊이·횡오차와 대조한다. 파일 해시가 빌드 보고서와 다르면 물리 실행을 시작하지 않는다.

성공 목표는 깊이 12~13 mm, 횡오차 0.05 mm 이하, 각도 0.5° 이하, 접촉 하중 25 N 이하, 상대 선속도 5 mm/s 이하·각속도 0.05 rad/s 이하를 0.4초 유지하는 것이다. INSERT 단계의 매 제어 주기에서 모든 물리 서브스텝과 마지막 시점이 조건을 만족해야 안정 시간을 누적한다. 저장한 원시 자세와 link-origin 속도는 NumPy 평가기로 다시 계산한다. 이 한계는 실험 설계값이다. 손목 F/T 센서 대신 PhysX 접촉값을 쓰며, 합력과 개별 법선력 절댓값의 합을 구분한다.

단일 환경의 명목 실행은 120 Hz와 240 Hz에서 모두 깊이·횡오차·각도·접촉 하중·원시 상대속도의 0.4초 연속 조건을 통과했다. 240 Hz 실행은 45.23초에 완료됐으며 마지막 깊이는 12.296 mm, 횡오차는 0.0033 mm 미만이었다. 같은 seed의 두 실행이므로 성공률이나 수치 수렴을 일반화하지 않는다.

이전 설정에서는 기하학적 삽입 상태에 도달해도 원시 각속도가 안정 조건을 넘었다. [PhysX 시뮬레이션 문서](https://nvidia-omniverse.github.io/PhysX/physx/5.7.0/docs/Simulation.html)의 split impulse 설명을 참고해 위치·속도 반복 수와 외력 적용 방식을 비교했다. 현재 설정은 로봇과 두 물체에 위치 반복 24회·속도 반복 0회·매 반복 외력 적용을 함께 사용한다. 상대속도 기준을 완화하거나 자세 차분값으로 바꾸지 않았으며, 삽입 기준점(entry/tip)의 상대속도를 강체 link-origin 원시 자세·속도에서 계산해 함께 기록한다. 성공한 실행과 이전 실패는 별도 출처 해시로 보존한다. 이전 실패의 설정과 결과는 [검증 근거](evidence/rj45-validation.json)에 있다.

학습용 초기 상태는 성공 기록 중 삽입 전 0.2초 동안 파지와 접촉이 유지된 구간에서 선택한다. 두 물체의 절대 선속도 5 mm/s·각속도 0.05 rad/s, 회전 관절 속도 0.05 rad/s·추종 오차 0.05 rad, 손가락 속도 5 mm/s·추종 오차 5 mm를 상한으로 검사한다. 손가락 목표와 실제 위치의 차이는 접촉을 유지하려는 닫힘 명령의 preload를 포함하며, 형상 침투량을 뜻하지 않는다. 이 한계는 실험 설계값이다. 복원 시에는 관절과 두 물체의 상태를 초기화 때만 쓰고, 이후 실제 물리 warmup을 거쳐 공유한 속도·관절 한계와 task의 힘 한계를 제어 주기마다 다시 검사한다. 반복 복원의 신뢰성은 GPU 검증이 끝난 뒤 보고한다.

## 재현

먼저 저장소 기본 에셋을 준비해야 한다. 기존 빌드 보고서에서 기본 그리퍼 치수를 읽으므로 RJ45 장면만 단독으로 생성하지 않는다.

```bash
cd "$HOME/rby1-assembly-lab"
.venv/bin/python scripts/fetch_assets.py
.venv/bin/python scripts/build_scene.py
python3 scripts/prepare_rj45_assets.py --conversion-python /usr/bin/python3
.venv/bin/python scripts/build_rj45_scene.py
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

STEP 변환에는 GLB export가 있는 KiCad 10과 `pcbnew`, NumPy, trimesh가 설치된 Python을 쓴다. USD 생성용 Python과 분리할 수 있다. 다운로드는 `configs/rj45-assets.json`의 URL·크기·SHA-256을 검사한다. 공급사 CAD·PDF와 변환 산출물은 Git에서 제외된 `assets/cache/rj45/`에 보관한다. 공급사 자료의 재배포 허가를 주장하지 않는다.

고정 버전 Isaac 환경을 설치한 Brev에서 실행한다.

```bash
cd "$HOME/rby1-assembly-lab"
OMNI_KIT_ACCEPT_EULA=YES .venv-isaac/bin/python scripts/run_sim.py \
  --headless --task rj45 --num-envs 1 \
  --trace artifacts/rj45/task-trace.jsonl \
  --report artifacts/rj45/task-report.json
```

`completed=false`는 완료된 삽입을 뜻하지 않는다. 정적 USD 생성, IK 해의 존재, 물리적 파지, 삽입 성공, 학습 개선은 각각 확인해야 한다.

기본 몸통 자세에서는 낮은 파지점에 접근할 작업 범위를 확보하려고, 몸통 관절을 `[0, 0.9, -1.8, 0.9, 0, 0] rad`로 움직인다. 상체 방향을 유지하며 높이를 약 264.9 mm 낮추는 설계 자세다. 관절 속도 명령을 따로 합성하지 않고 공통 진행률의 위치 목표를 사용한다. 팔 경유 자세에 도달하기 전에는 몸통을 내리지 않는다. 두 손은 열린 손가락 형상을 포함한 접근 경유점을 거쳐 내려온다.

단일 환경 RJ45 실행은 좌우 손의 9개 강체 접촉쌍을 활성화하고 하중을 평가기에 전달한다. 이 감시는 명령이나 힘을 주입하지 않는다. 나머지 내부 로봇 접촉쌍은 필터링되며 전신 자체 충돌 회피를 검증한 것으로 표시하지 않는다. 4환경 양손 접촉 감시는 두 환경의 실제 접촉 하중과 나머지 환경의 0 N, reset 후 0 N, 환경 간 충돌 음성 대조를 통과했다. 실행기는 보고서·trace·실제 body pose의 교차 검사와 소스 해시가 일치하는 증거를 요구한다. 이 통과는 전체 조립 과제의 병렬 실행 성공을 뜻하지 않으며 실제 실행에서 센서의 환경별 순서도 다시 확인한다.

## 강화학습으로 확인할 내용

정렬·삽입 학습에서는 정책과 기준 제어가 같은 관측 오차를 받는다. 파지 때 한 번 얻은 손과 물체의 관계를 고정한 뒤 관절 운동학으로 물체 자세를 추정하며, 실제 물체 미끄러짐을 정답 위치로 다시 보정하지 않는다. 79차원 관측에는 추정 상대 자세, 관절 상태, 접촉 하중, 단계와 이전 보정값이 포함된다. 오른팔 6차원 보정과 양팔 12차원 보정을 비교할 수 있다.

초기 실험은 파지 후 정렬·삽입 범위와 보정 오차에 한정한다. 마찰·질량 무작위화는 사용하지 않는다. 같은 조건·시드의 정답 보정 기준 제어, 오차가 있는 zero-residual 기준 제어, 학습 정책을 비교한다. 공통 비교 키와 실제 적용 오차는 따로 저장한다. 테이블에서 집어 드는 전체 과제 평가는 초기 스크립트 제어 뒤 같은 추정기로 전환한다. 학습에 쓰지 않은 조건의 성공률·재시도·완료 시간·최대 하중을 보고해야 강화학습의 효과를 판단할 수 있다.

학습 명령은 `completed=true`인 RJ45 명목 실행을 증거로 요구한다. 보고서와 모든 제어 주기의 trace가 이어지는지, 성공 판정이 원시 자세에서 독립적으로 다시 계산되는지, 파지 상태 artifact와 런타임 버전·물리·제어 주기, 소스·설정·생성 USD·다운로드 에셋 해시가 현재 실행과 같은지 먼저 검사한다. 체크포인트 평가도 학습 당시 계약과 체크포인트 자체의 해시를 다시 확인한다. 하나라도 맞지 않으면 학습이나 평가를 시작하지 않는다.

기존 toy 삽입 성공 영상과 PPO 스모크는 이 RJ45 과제의 성공 또는 학습 성능 근거로 사용하지 않는다. RJ45 정책은 아직 학습하지 않았다.
