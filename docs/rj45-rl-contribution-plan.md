# RJ45 강화학습 기여 검증 재개 계획

기준일: 2026-10-30. 사용자는 주말 공개보다 강화학습의 기여를 검증하는 일을 우선하고, 추가 학습과 Brev 사용을 허용했다. 기존 실험·사전등록·실패 기록은 보존한다. 이 문서는 다음 실험의 설계와 실행 전 조건이며, GPU 실험을 시작했다는 기록은 아니다.

## 목표와 주장 범위

RB-Y1이 왼손으로 휴대형 LAN 어댑터를 지지하고 오른손으로 RJ45 플러그를 삽입할 때, PPO 학습이 기존 제어와 시연 학습에 더하는 효과를 검증한다. 주된 지표는 기존 strict-v1의 독립 삽입 성공률이다. 접촉 하중, 완료 시간, 삽입 후 상대 속도, 안정 유지 시간과 학습 비용을 함께 보고한다.

현재 정책은 INSERT 단계의 오른손 6차원 팁 목표 보정만 결정한다. 삽입 깊이 진행, 단계 전환, 힘에 따른 중단, 후퇴와 복구는 스크립트가 결정한다. 먼저 이 supervisor를 고정한 채 학습 보정의 효과를 검증한다. 양팔 전체 제어, 학습된 후퇴·잼 복구, 카메라 정책 또는 실물 전이를 현재 결과로 표현하지 않는다.

50 µm는 프로젝트의 횡오차 평가 기준이다. 접촉 입력은 PhysX proxy이며, 실물 센서나 제조사 조립 규격의 검증값이 아니다.

기준 제어기는 학습 보정을 0으로 둔 비교군이다. 참조 제어기(reference controller)는 시뮬레이터 정답 상태로 시연 행동을 생성한다. BC 정책은 시연 데이터로 행동을 학습하고, PPO 정책은 시뮬레이션 rollout의 보상으로 갱신한다. 참조 제어기의 정답 상태는 학습 정책 관측에 추가하지 않는다. 기존 데이터 스키마·파일명·동결 프로토콜의 식별자는 유지한다.

## 실행 순서와 중간 판단

### G0. 자료와 실행 조건 복구

- 남기기로 한 인스턴스는 `rby1-rj45-4gpu-aws-20261028` / `ndntytgdv` 한 대다. 다른 프로젝트 인스턴스는 조작하지 않는다.
- 원격에 남은 새 bank, report, trace, proof와 종료 기록을 회수하고 파일 해시를 대조한다. 결과가 없거나 실패했다면 그 상태를 보존한다.
- 실제 사용 가능 잔액·요금과 프로젝트 지출을 확인한다. 최신 예약 기록은 `artifacts/cloud/rj45-warmup-completion-budget-20261028.json`의 $650.45072이며, SHA-256은 `793fbbbbc52731c5ba638e4dc64402fbaf9d9364440b7f1c4ad5cdab41802961`이다. 이 파일은 이전 `rj45-warmup-recovery-budget-20261028.json`의 $570.26072에서 실행 한도를 연장한 기록이며 실제 청구액이 아니다. 기존 승인 한도 $700을 자동으로 늘리지 않는다.
- 학습과 렌더가 같은 인스턴스에서 동작하는 런타임을 먼저 확인한다. 기존 595 드라이버의 카메라 smoke 실패와 별도 580 서버의 촬영 성공 기록을 참조한다. 런타임을 바꾸면 필요한 물리 검증을 새로 수행한다.
- 지난 실행의 만료된 deadline·비활성 타이머를 재사용하지 않는다. 새 실행마다 종료 시각, 예상 비용, 입력 해시와 회수 경로를 고정한다.
- 10월 30일 콘솔의 기동 실패 상세창에서 지역 GPU 용량 부족 오류를 확인했다. 기존 인스턴스의 자료를 보존하며 회수를 재시도한다. 현재 CLI와 콘솔에서는 기존 볼륨을 유지하는 타입·리전 변경 경로를 확인하지 못했으므로, 초기화·삭제로 우회하지 않는다.

완료 조건: 회수 자료의 상태와 계보가 확인되고, 비용 한도와 새 실행 조건이 정해져 있어야 GPU 실험을 시작한다.

### G1. 기존 정책의 실패 시점 분석

승인된 기준 제어 env54와 BC env54·env42의 원본 프레임 JSONL을 먼저 사용한다. 프레임 시각과 제어 시각을 구분하고, 60fps 프레임에 반복된 같은 제어 스냅샷을 독립 표본으로 세지 않는다.

분석 항목은 행동·이전 행동·실제 적용한 목표 보정, 추정 상대 자세, 물리 속도, 안정성 하위 조건, dwell과 최초 이탈 시각이다. 종료 시점의 형상만으로 전 구간의 실패 원인을 정하지 않는다. 선택된 세 촬영 사례의 결과를 전체 성공률이나 인과 효과로 확대하지 않는다.

완료 조건: 다음의 작은 시험에서 구분할 가설과 관측할 지표가 정해져 있어야 한다. 기존 자료에 없는 신호는 추정해 채우지 않는다.

### G2. 한 학습 조건에서 제어·학습 가능성 확인

train 파지 한 개와 train 보정 조건 한 개를 고정한다. dev/final을 이 진단의 학습 데이터로 사용하지 않는다.

1. 참조 제어기가 해당 조건에서 성공하는지 확인한다.
2. BC 정책이 그 조건의 시연 행동을 충분히 맞출 수 있는지 검사한다.
3. 해당 BC 정책을 물리 환경에서 실행해 폐루프 성공과 안정화를 확인한다.
4. 물리 평가가 실패하면 행동 적용·시간 정렬·관측·제어 권한을 구분한다.

행동을 항상 0으로 내는 기준뿐 아니라 train 평균 행동을 항상 내는 기준과 축별 오차를 비교한다. 작은 전체 MSE가 평균 행동만 학습한 결과인지 구분해야 한다. [첫 CPU 진단](evidence/rj45-train-condition-probe-20261030/fit-result.json)은 zero 대비 사전 기준을 통과했지만 평균 행동 기준과 오차가 비슷했다. 따라서 상태에 따른 경로 추종과 G2 완료는 아직 입증되지 않았다. 후속 회귀 진단의 판정 기준은 해당 실행 전에 고정하며, 기존 기준과 결과는 보존한다.

이 단계는 일반화 성능이나 본실험의 성공률에 합산하지 않는다. 고정 조건에서도 폐루프 제어가 되지 않으면 장기 다중-seed 학습으로 넘어가지 않는다.

[후속 학습률 비교](evidence/rj45-g2-optimizer-probe-20261030/README.md)는 현재 CPU 런타임에서 같은 초기 actor와 입력을 사용해 `1e-3`과 `1e-4`를 각각 2,000 step 실행했다. 낮춘 학습률은 말미 오차가 단조 감소했지만 평균 행동 기준과 충분한 차이를 만들지 못했고, 기존 학습률보다도 오차가 컸다. 사전 기준은 FAIL이며 G2의 회귀·폐루프 검증은 미완료다. 이 결과로 최적화 전체, 관측 정보 또는 시연 데이터 중 하나를 원인으로 확정하지 않는다. 실행 전 고정한 두 비교를 마쳤고, 후속 라벨 변환·관측 변경은 별도 프로토콜에서 검증해야 한다.

[축별 손실 비교](evidence/rj45-g2-axis-scaling-20261030/README.md)에서는 같은 BC 구조·초기값·학습률·횟수를 유지하고, 6개 명령 축의 오차를 train 시연의 축별 표준편차로 나눠 학습했다. 같은 조건의 비가중 손실 대비 원래 명령 좌표의 MSE가 약 6.9% 낮았지만, 상수 평균 대비 비율 `0.9180`과 축 균형 MSE `0.9298`이 각각 사전 기준 `0.90`을 넘었다. 축별 오차 비중 조정의 부분적인 효과는 관찰했지만 진단 통과와 G2 완료는 아니다. 다음 비교는 이 손실 함수를 고정하고 train 데이터로 계산한 입력 표준화만 바꾼다. 미세 변동을 과도하게 확대하지 않도록 표준편차 하한과 상수 축 처리를 실행 전에 고정하고, 추론에도 같은 변환을 적용한다. 실제 관측 정보와 참조 제어기의 시연 명령이 충분히 대응하는지는 별도 질문으로 남는다.

[입력 표준화 비교](evidence/rj45-g2-input-normalization-20261030/README.md)는 축별 가중 손실을 유지한 A를 먼저 재현한 뒤, 같은 79D 입력의 train 통계로 표준화한 B를 학습했다. B의 원래 명령 좌표 MSE는 A의 `15.87%`, 상수 평균의 `14.57%`였고 축 균형 MSE는 `0.1539`로 사전 오프라인 진단 기준을 통과했다. 표준편차 하한은 `1e-4`로 사전 고정했고 입력 통계와 마스크를 체크포인트에 저장해 재로딩 추론을 검증했다. 조건부 대조에서 이전 명령 12열을 제거한 정책은 B보다 MSE가 약 2.18배 컸고, 추정 상대 자세 7열 제거는 약 1.06배로 판단 보류였다. 이 결과는 이전 명령 복사 또는 상대 자세 피드백의 인과 효과를 확정하지 않는다.

G2의 같은 궤적 회귀 진단은 통과했으며, 단일 조건 물리 폐루프 성공과 안정화는 미완료다. 다음은 고정 train 파지·보정 조건의 1환경에서 A/B를 같은 초기 상태·seed로 비교하는 물리 진단이다. 입력 전처리가 제어 루프에서도 동일하게 적용되는지 검증하고 독립 삽입 성공·안정 유지·중단·접촉 하중을 기록한다. 이 물리 검증을 통과한 뒤에만 전체 시연 데이터의 BC 재학습과 PPO 비교에 적용하며, 현재 한 궤적의 진단 체크포인트를 본실험에 주입하지 않는다.

### G3. 근거에 맞는 개선 한 가지 선택

| 확인할 현상 | 단일 변경 후보 | 별도 검증 조건 |
| --- | --- | --- |
| 참조 제어기는 학습 정책 방문 상태에서 회복하지만 학습 정책은 실패한다. | 학습 정책 rollout의 상태에 참조 제어기 행동을 추가하는 DAgger형 데이터 보강 | 성공 경로·실패·참조 제어기 회복 불가 사례를 모두 보존하고 train 상태만 학습에 사용한다. |
| 정렬 이후에도 움직임이 남아 유지 조건이 깨진다. | 정렬·삽입 조건에서 활성화되는 안정화 보상 또는 보정 감쇠 | 보상과 감쇠를 한 번에 바꾸지 않는다. 기존 성공 조건은 유지한다. |
| 필요한 상태 차이가 현재 관측에서 구분되지 않는 증거가 있다. | 추정 상대 속도 또는 짧은 접촉·움직임 이력 | 현재 actor가 받는 추정값과 과거 값으로 계산한다. 정답 물체 속도나 평가기의 GT dwell을 학습 정책 입력에 넣지 않는다. |
| 학습 정책뿐 아니라 참조 제어기도 해당 상태에서 회복하지 못한다. | 참조 제어기 또는 제어 권한·과제 설계 검토 | 같은 데이터만 늘리는 경로는 중단한다. 환경 변경은 별도 버전과 새 기준선을 요구한다. |

참조 제어기 리라벨링은 학습 정책이 행동하는 시각의 상태에 라벨을 붙이되, 참조 제어기 계산이 학습 정책 실행 상태를 바꾸지 않는 경로로 구현한다. 학습 정책 관측, 실행한 학습 정책 행동, 참조 제어기가 제안한 행동, 유효성·실패 이유와 시각을 분리한다. 복원한 물리 상태가 원래 접촉 상태와 동일하다고 가정하지 않는다.

이 live shadow-query 수집 경로는 현재 구현돼 있지 않다. 구현 후 상태 비변경, 시각 정렬, GT의 학습 정책 입력 누출 방지와 실제 물리 실행 검증을 통과해야 데이터 수집에 사용한다.

이전 행동을 0으로 만든 오프라인 시험은 분포 밖 입력일 수 있다. 그 결과나 국소 Jacobian만으로 shortcut 또는 로봇 불안정을 확정하지 않는다.

[전체 train 시연 대조](evidence/rj45-teacher-forced-baselines-20261030/README.md)에서는 기존 BC가 전체 평균 행동보다 낮은 MSE를 보였지만 직전 참조 제어기 행동 복사와의 차이는 작았다. 단일 조건의 평균 행동 진단을 전체 BC가 상태를 사용하지 않는다는 주장으로 확대하지 않는다. 참조 제어기가 만든 이전 행동과 학습 정책 실행 뒤의 이전 행동은 구분하고, 학습 정책 방문 상태에서의 참조 제어기 리라벨링과 폐루프 검증을 다음 데이터 비교의 근거로 삼는다. 이 분석도 실패 원인의 인과 증명은 아니다.

### G4. 강화학습의 추가 기여 비교

| 군 | 출발점과 학습 | 답할 질문 |
| --- | --- | --- |
| 기준 제어 | 학습 보정 0 | 현재 제어의 성공·안전·시간 기준은 무엇인가? |
| BC-only | 고정한 참조 제어기 데이터로 학습한 actor | 시연 학습만의 효과는 무엇인가? |
| PPO-only | 기존과 같은 잔차 초기화에서 PPO | 시연 없이 online 학습한 결과는 무엇인가? |
| BC→PPO | BC-only와 같은 actor checkpoint에서 PPO | PPO를 추가한 이득이 있는가? |

- 모든 군의 물리·supervisor·관측·행동·평가 조건을 맞춘다. 비교하려는 한 요소만 바꾼다.
- PPO 두 군은 환경 전이 수와 checkpoint 선택 규칙을 맞춘다. 참조 제어기 시뮬레이션과 BC의 추가 비용은 별도 보고한다.
- 같은 seed의 PPO 두 군은 초기화 전 actor·critic·탐색분포·optimizer와 Python·NumPy·Torch CPU·해당 CUDA 장치 RNG fingerprint가 같아야 한다. 초기화 후에는 actor만 달라지고 critic·탐색분포·optimizer·RNG가 같아야 한다. 실행 기록이 이 조건을 확인하지 못하면 paired 비교를 시작하지 않는다.
- 200 update가 수렴을 보장한다고 가정하지 않는다. pilot은 train 파지·train 보정 조건만 사용하는 탐색으로 두고, 그 결과와 모델을 본실험 결과에 합산하거나 본실험 checkpoint로 이어 쓰지 않는다. pilot의 처리량·학습 곡선으로 본실험의 전이 예산과 마지막 판정 checkpoint를 정한다.
- 본실험 전에 source/config/data 해시, seed 목록, horizon, 총 전이 수, 마지막 판정 checkpoint, 중간 진단 checkpoint, 평가 사례와 실제 bias 목록, 실행 순서, 집계 방법과 불확실성 계산을 별도 사전등록으로 고정한다. 중간 결과를 보고 예산·checkpoint·성공 기준을 바꾸지 않는다.
- 과거 개발 64조건과 G1의 촬영 사례는 가설 탐색에 사용한 자료다. 새 독립 검증처럼 재명명하지 않는다. 본실험은 사용하지 않은 고정 개발 보정 조건을 dev 파지에 배정하고 마지막 checkpoint로 한 번 승격 여부를 판단한다. 이 개발 판단도 최종 성능 주장을 대신하지 않는다.
- 최소 3개의 독립 학습 seed를 사용한다. 5개로 확대할 경우 그 수와 비용을 본실험 전에 고정한다. 결과를 보고 유리해질 때까지 seed를 추가하지 않는다.
- 새 개발 비교에서는 BC→PPO가 기준 제어·PPO-only·같은 BC-only 각각보다 평균 6/64 이상 높아야 승격한다. 기존 동결 실험에는 새 BC-only 조건을 소급 적용하지 않는다.
- 최종 평가에서 강화학습의 추가 기여 판정은 같은 BC-only 대비 성공률 차이가 평균 9.375%p 이상이고, 짝지은 95% 구간의 하한이 0보다 크며, 학습 seed 과반에서 차이가 양수일 때로 고정한다. 무효 episode 0과 금지 접촉 하중 0도 요구한다. 최종 표본 수가 64와 다르면 6건이 아니라 이 비율을 적용한다.
- 불확실성 구간은 학습 seed와 같은 파지 안의 짝지은 보정 사례를 재표집하는 계층 bootstrap으로 계산한다. 100,000회, 분석 seed `20261030`을 고정하고 실패 사례를 제외하지 않는다. 이 구간은 고정한 BC checkpoint와 최종 파지 표본에 조건부이며, 모든 파지·형상의 모집단으로 확대하지 않는다.
- 최종 차이가 0 이하이거나 안전·유효성 조건을 위반하면 개선 실패로 판정한다. 차이가 양수여도 최소 효과·구간·seed 조건 중 하나라도 만족하지 못하면 증거 불충분으로 판정하고 추가 기여를 확정하지 않는다. 낮은 최종 결과에 맞춰 같은 final 분할을 재학습에 사용하지 않는다.
- seed별 결과, 사례별 짝지은 차이와 불확실성, 무효·실패·접촉·시간을 함께 보고한다. 보상 합계나 BC MSE로 실제 성공률을 대체하지 않는다.
- 기존 동결 protocol JSON과 과거 결과는 수정하지 않는다. 새 실행의 설정·예산·seed·선택 규칙은 별도 사전등록으로 고정한다.

완료 조건: PPO의 이득이 BC 초기화 또는 시연 데이터의 이득과 구분돼야 한다. BC만 좋아지고 BC→PPO가 좋아지지 않으면 시연 학습의 결과로 기록하고 PPO 성공으로 표현하지 않는다.

### G5. 미사용 조건과 지지팔 비교

후보와 checkpoint 선택을 끝낸 뒤 final 파지·보정 조건을 평가한다. 최종 결과를 보고 같은 분할에 맞춰 재학습하지 않는다. 현재 final 파지가 두 개인 검증은 그 작은 범위에 한정해 설명한다.

지지팔 제어 비교는 현재 도구의 실제 권한과 동일한 Cartesian 보정 예산을 확인한 뒤 수행한다. 스크립트 지지팔 비교를 학습된 양팔 12D 정책으로 표현하지 않는다. 양팔 정책과 학습된 후퇴·복구는 이 검증 이후 별도 과제다.

### G6. 포트폴리오 납품

최종 정책과 기준 제어의 동기 비교, 실제 정책 실패 약 두 편, 성공률·안전·시간·seed 편차 그래프와 재현 명령을 묶는다. 학습 전후의 동일 조건과 정책 해시를 영상·보고서에 연결한다. 실패 또는 불확실한 결과도 원본 근거에 보존한다. 독립 검토 후 로컬 커밋, 승인된 main 반영·push와 원격 SHA 대조를 완료한다.

## 로컬과 Brev의 역할

로컬은 기존 rollout·HDF5 분석, 작은 BC 회귀, 단위 계산, 그래프·문서에 사용한다. 현재 RTX 5050 Laptop 8GB와 드라이버 불일치·저장 여유 상태에서는 고정 Isaac 5.1 환경의 물리 실행 가능 여부를 확인하지 못했다.

Brev 한 인스턴스에서 물리 재현, 참조 제어기 리라벨링, 폐루프 진단과 PPO를 수행한다. GPU별로 독립 실행을 배치할 수 있지만 네 GPU를 정책 한 개의 분산 학습으로 사용했다고 표현하지 않는다. 실험을 마친 뒤 결과를 회수하고 인스턴스를 정지한다.
