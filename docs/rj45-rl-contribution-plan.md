# RJ45 강화학습 기여 검증 재개 계획

기준일: 2026-10-31. 사용자는 주말 공개보다 강화학습의 기여를 검증하는 일을 우선하고, 추가 학습과 Brev 사용을 허용했다. 기존 실험·사전등록·실패 기록은 보존한다. 10월 31일 사용자는 RB-Y1 양팔 커넥터 조립 테마를 유지하면서 관측·보상·행동 권한을 진단하고, 필요한 경우 SAC를 대조하는 개선 순서를 승인했다. 실험 결과는 단계별 근거 문서로 구분한다.

## 목표와 주장 범위

RB-Y1이 왼손으로 휴대형 LAN 어댑터를 지지하고 오른손으로 RJ45 플러그를 삽입할 때, PPO 학습이 기존 제어와 시연 학습에 더하는 효과를 검증한다. 주된 지표는 기존 strict-v1의 독립 삽입 성공률이다. 접촉 하중, 완료 시간, 삽입 후 상대 속도, 안정 유지 시간과 학습 비용을 함께 보고한다.

현재 정책은 INSERT 단계의 오른손 6차원 팁 목표 보정만 결정한다. 삽입 깊이 진행, 단계 전환, 힘에 따른 중단, 후퇴와 복구는 스크립트가 결정한다. 먼저 이 supervisor를 고정한 채 학습 보정의 효과를 검증한다. 양팔 전체 제어, 학습된 후퇴·잼 복구, 카메라 정책 또는 실물 전이를 현재 결과로 표현하지 않는다.

50 µm는 프로젝트의 횡오차 평가 기준이다. 접촉 입력은 PhysX proxy이며, 실물 센서나 제조사 조립 규격의 검증값이 아니다.

기준 제어기는 학습 보정을 0으로 둔 비교군이다. 참조 제어기(reference controller)는 시뮬레이터 정답 상태로 시연 행동을 생성한다. BC 정책은 시연 데이터로 행동을 학습하고, PPO 정책은 시뮬레이션 rollout의 보상으로 갱신한다. 참조 제어기의 정답 상태는 최종 성능을 평가하는 실행 정책 관측에 추가하지 않는다. 정답 상태를 받는 oracle actor는 원인 분리를 위한 별도 진단이며, 그 결과를 실행 정책이나 일반화 성능으로 합산하지 않는다. 기존 데이터 스키마·파일명·동결 프로토콜의 식별자는 유지한다.

## 실행 순서와 중간 판단

### G0. 자료와 실행 조건 복구

- 기존 `rby1-rj45-4gpu-aws-20261028` / `ndntytgdv`와 G2 서버 `rby1-g2-l40s-20261031` / `g4xfquxz3`의 볼륨을 보존한다. AWS 서버가 지역 GPU 용량 부족으로 재기동되지 않아, 기존 추가 서버 승인 범위에서 Crusoe `rby1-oracle-crusoe-20261031a` / `pyf1b9s0a`를 만들었다. L40S 1장 구성으로 실행하며 다른 프로젝트 인스턴스는 조작하지 않는다.
- 원격에 남은 새 bank, report, trace, proof와 종료 기록을 회수하고 파일 해시를 대조한다. 결과가 없거나 실패했다면 그 상태를 보존한다.
- 실제 사용 가능 잔액·요금과 프로젝트 지출을 확인한다. 과거 G2의 예약 합계 $696.31822와 첫 oracle 진단의 $699.31822는 실제 청구액이 아니며 [당시 결과](evidence/rj45-g2-physics-20261031/result.json)에 보존한다. 후속 실행 전 인증된 Billing의 인스턴스별 표시액과 미청구·스토리지 여유분을 별도로 대조했다. 불확실한 사용액은 프로젝트 비용에 포함했고, 실패한 재기동과 대체 서버를 합친 새 예약 상한은 $12다. 공개 [입장권](../configs/rj45-oracle-admission-20261031.json)에는 비공개 확인 기록의 SHA와 상한만 남긴다. 계정 잔액·다른 프로젝트 사용액은 공개하지 않으며 승인 한도 $700을 늘리지 않는다.
- 학습과 렌더가 같은 인스턴스에서 동작하는 런타임을 먼저 확인한다. 기존 595 드라이버의 카메라 smoke 실패와 별도 580 서버의 촬영 성공 기록을 참조한다. 런타임을 바꾸면 필요한 물리 검증을 새로 수행한다.
- 지난 실행의 만료된 deadline·비활성 타이머를 재사용하지 않는다. 새 실행마다 종료 시각, 예상 비용, 입력 해시와 회수 경로를 고정한다.
- 후속 상수·재생 대조는 기존 L40S 한 대에서 추가 예약 $6를 사용했다. 무효 첫 시도와 수정 실행이 이 예약을 공유하며, 이전 $12 예약을 해제한 것으로 계산하지 않았다. 비공개 비용 대조로 전체 $700 상한을 확인한 [공개 입장권](evidence/rj45-frozen-ablation-20261031/budget-admission.json)을 보존한다. 예약은 실제 청구액이 아니다.
- 10월 30일 콘솔의 기동 실패 상세창에서 지역 GPU 용량 부족 오류를 확인했다. 기존 인스턴스의 자료를 보존하며 회수를 재시도한다. 현재 CLI와 콘솔에서는 기존 볼륨을 유지하는 타입·리전 변경 경로를 확인하지 못했으므로, 초기화·삭제로 우회하지 않는다.

완료 조건: 회수 자료의 상태와 계보가 확인되고, 비용 한도와 새 실행 조건이 정해져 있어야 GPU 실험을 시작한다.

### G1. 기존 정책의 실패 시점 분석

승인된 기준 제어 env54와 BC env54·env42의 원본 프레임 JSONL을 먼저 사용한다. 프레임 시각과 제어 시각을 구분하고, 60fps 프레임에 반복된 같은 제어 스냅샷을 독립 표본으로 세지 않는다.

분석 항목은 행동·이전 행동·실제 적용한 목표 보정, 추정 상대 자세, 물리 속도, 안정성 하위 조건, dwell과 최초 이탈 시각이다. 종료 시점의 형상만으로 전 구간의 실패 원인을 정하지 않는다. 선택된 세 촬영 사례의 결과를 전체 성공률이나 인과 효과로 확대하지 않는다.

완료 조건: 다음의 작은 시험에서 구분할 가설과 관측할 지표가 정해져 있어야 한다. 기존 자료에 없는 신호는 추정해 채우지 않는다.

### G2. 한 학습 조건에서 제어·학습 가능성 확인

train 파지 한 개와 train 보정 조건 한 개를 고정한다. dev/final을 이 진단의 학습 데이터로 사용하지 않는다.

1. 참조 제어기가 해당 조건에서 성공하는지 확인한다.
2. BC 정책이 그 조건의 시연 행동을 충분히 맞출 수 있는지 검사한다.
3. 해당 BC 정책을 물리 환경에서 실행해 폐루프 성공과 안정화를 확인한다.
4. 물리 평가가 실패하면 행동 적용·시간 정렬·관측·제어 권한을 구분한다.

행동을 항상 0으로 내는 기준뿐 아니라 train 평균 행동을 항상 내는 기준과 축별 오차를 비교한다. 작은 전체 MSE가 평균 행동만 학습한 결과인지 구분해야 한다. [첫 CPU 진단](evidence/rj45-train-condition-probe-20261030/fit-result.json)은 zero 대비 사전 기준을 통과했지만 평균 행동 기준과 오차가 비슷했다. 따라서 상태에 따른 경로 추종과 G2 완료는 아직 입증되지 않았다. 후속 회귀 진단의 판정 기준은 해당 실행 전에 고정하며, 기존 기준과 결과는 보존한다.

이 단계는 일반화 성능이나 본실험의 성공률에 합산하지 않는다. 고정 조건에서도 폐루프 제어가 되지 않으면 장기 다중-seed 학습으로 넘어가지 않는다.

[후속 학습률 비교](evidence/rj45-g2-optimizer-probe-20261030/README.md)는 현재 CPU 런타임에서 같은 초기 actor와 입력을 사용해 `1e-3`과 `1e-4`를 각각 2,000 step 실행했다. 낮춘 학습률은 말미 오차가 단조 감소했지만 평균 행동 기준과 충분한 차이를 만들지 못했고, 기존 학습률보다도 오차가 컸다. 사전 기준은 FAIL이며 G2의 회귀·폐루프 검증은 미완료다. 이 결과로 최적화 전체, 관측 정보 또는 시연 데이터 중 하나를 원인으로 확정하지 않는다. 실행 전 고정한 두 비교를 마쳤고, 후속 라벨 변환·관측 변경은 별도 프로토콜에서 검증해야 한다.

[축별 손실 비교](evidence/rj45-g2-axis-scaling-20261030/README.md)에서는 같은 BC 구조·초기값·학습률·횟수를 유지하고, 6개 명령 축의 오차를 train 시연의 축별 표준편차로 나눠 학습했다. 같은 조건의 비가중 손실 대비 원래 명령 좌표의 MSE가 약 6.9% 낮았지만, 상수 평균 대비 비율 `0.9180`과 축 균형 MSE `0.9298`이 각각 사전 기준 `0.90`을 넘었다. 축별 오차 비중 조정의 부분적인 효과는 관찰했지만 진단 통과와 G2 완료는 아니다. 다음 비교는 이 손실 함수를 고정하고 train 데이터로 계산한 입력 표준화만 바꾼다. 미세 변동을 과도하게 확대하지 않도록 표준편차 하한과 상수 축 처리를 실행 전에 고정하고, 추론에도 같은 변환을 적용한다. 실제 관측 정보와 참조 제어기의 시연 명령이 충분히 대응하는지는 별도 질문으로 남는다.

[입력 표준화 비교](evidence/rj45-g2-input-normalization-20261030/README.md)는 축별 가중 손실을 유지한 A를 먼저 재현한 뒤, 같은 79D 입력의 train 통계로 표준화한 B를 학습했다. B의 원래 명령 좌표 MSE는 A의 `15.87%`, 상수 평균의 `14.57%`였고 축 균형 MSE는 `0.1539`로 사전 오프라인 진단 기준을 통과했다. 표준편차 하한은 `1e-4`로 사전 고정했고 입력 통계와 마스크를 체크포인트에 저장해 재로딩 추론을 검증했다. 조건부 대조에서 이전 명령 12열을 제거한 정책은 B보다 MSE가 약 2.18배 컸고, 추정 상대 자세 7열 제거는 약 1.06배로 판단 보류였다. 이 결과는 이전 명령 복사 또는 상대 자세 피드백의 인과 효과를 확정하지 않는다.

[고정 조건 PhysX 비교](evidence/rj45-g2-physics-20261031/README.md)에서 기존 입력 A는 13.267초에 독립 삽입 성공을 통과했고, 정규화 입력 B는 24초 후 실패했다. 같은 protocol·bank·첫 관측을 사용했으며 서버의 395행 예측 해시도 로컬과 일치했다. B는 이전 명령 관측의 학습 범위 이탈 이후 큰 보정과 물리 정렬 오차 증가를 보였다. 단일 조건에서 관찰한 순서이며 정규화를 원인으로 확정하지 않는다. 같은 궤적의 회귀 개선이 물리 개선으로 이어지지 않았으므로 B를 승격하거나 본실험에 주입하지 않는다. 아래 oracle PPO 진단을 다음 실행으로 두고, 참조 행동 리라벨링은 회복 가능성이 확인될 때 선택한다. BC 완성을 모든 PPO 실험의 선행 조건으로 두지 않는다.

#### G2 후속: oracle PPO와 표준 관측 비교

목적은 PPO가 이 환경에서 보정 행동을 학습할 수 있는지, 실행 정책의 관측 부족과 최적화·보상·제어 권한 문제를 구분하는 것이다. 기존 `104721a` 물리 소스와 train bank의 계보를 유지하고, 별도 관측 어댑터와 실행기를 주입한다. 최초 실행은 1환경의 고정 train 조건이며 병렬 처리량이나 다중 조건 성능 비교가 아니다.

- `zero`: 같은 제어에서 학습 보정 없이 실행한다.
- `reference`: 같은 오른손 보정 한도에서 정답 상태를 사용하는 참조 제어기를 실행한다.
- `standard79`: 실행 actor는 기존 79D, critic은 기존 관측과 정답 상대 자세·상대 twist 13D를 합친 92D를 받는다.
- `oracle92`: 진단 actor와 critic 모두 위의 92D를 받는다. 정답 관측 actor 결과는 진단에만 사용한다.

두 학습군의 critic 입력 정의는 같다. 정답 상대 속도는 socket-entry 회전 좌표계에서 tip/entry 레버암과 회전 수송항을 포함해 계산한다. 물리·행동 한도·보상·종료·초기화 검사는 그대로 두고, 관측 변경만 비교한다. 초기 결정론적 actor와 마지막 사전 지정 checkpoint를 같은 고정 조건에서 평가하며, 워밍업과 유효 제어 시각을 구분한다. 실행 전 입력 해시·학습 seed·전이 예산·최종 checkpoint·시간 및 비용 상한을 프로토콜로 고정한다.

PPO 갱신·return·advantage·손실의 유한성, actor 변경, 행동 포화, 탐색 표준편차와 접촉·엄격 판정을 기록한다. 짧은 실행이 끝났다는 사실을 수렴이나 효과 입증으로 표시하지 않는다. `zero`도 성공한 조건은 실행 경로 검사에 쓸 수 있지만 비자명한 학습 기여를 보여주는 조건으로 승격하지 않는다. 무보정 실패·참조 복구 성공 사례는 진단에만 사용하고, dev/final 성능 평가의 분모에 넣지 않는다.

oracle도 학습되지 않으면 PPO가 불가능하다거나 보상 하나가 원인이라고 단정하지 않는다. 동작 적용·갱신·종료 처리와 제어 가능성을 확인한 뒤, 같은 관측·보상·데이터 권한에서 SAC를 한 번의 조건부 대조로 검토한다. oracle은 학습되고 표준 관측에서 실패하면 추정 상대 속도·접촉 이력과 안정화 보상을 각각 별도 대조한다. privileged critic만 추가한다고 actor의 정보 부족이 해결되는 것으로 보지 않는다.

[첫 원격 사전 진단](evidence/rj45-oracle-ppo-20261031/README.md)은 zero/reference의 trace 기록을 마친 뒤 보고서 직렬화 오류로 중단됐다. 두 보고서는 invalid이며 PPO 두 군은 실행하지 않았다. 오류와 종료 코드 처리를 수정하고 회귀 검사를 추가했다. 오류 이전 trace에는 zero도 성공 판정이 있어, 이번 고정 조건을 학습 기여 검증으로 승격하지 않는다. 다음 진단 조건과 프로토콜은 새로 고정하며, 기존 동결 프로토콜과 무효 실행을 보존한다.

[무보정 실패 조건의 후속 진단](evidence/rj45-oracle-condition-20261031/README.md)에서 `20261128`의 train 조건은 zero 실패와 참조 성공을 보였다. 수정된 실행기로 standard79를 32 updates·4,096 transitions 학습했을 때 초기 횡오차 87.50 µm 실패가 최종 28.00 µm 성공으로 바뀌었다. 단일 조건의 학습 가능성 근거이며 여러 조건의 개선이나 상태 피드백 학습을 입증하지 않는다. 원본 oracle 실행의 최종 평가 오류와 checkpoint 평가 복구는 보존하고, primary 비교에는 같은 수정 소스의 새 oracle32만 사용한다. 새 oracle92도 31.67 µm로 성공했고, 초기 actor 공통 투영·critic·optimizer·RNG와 입력 계보의 primary 감사를 통과했다. 두 군의 성공만으로 관측 부족이나 정보 충분성을 결론 내리지 않는다. 다음 구분 과제는 상수 보정 대조와 미사용 개발 보정 조건의 paired 평가다. 사전 고정한 감사 실패 시 대체 실행을 금지하는 규칙은 유지한다.

[고정 정책의 후속 20회 대조](evidence/rj45-frozen-ablation-20261031/README.md)는 학습 조건의 PPO·상수·재생 성공과 무보정 실패를 확인했다. 같은 train 파지의 새 보정 오차 네 개에서는 무보정 4/4, PPO·상수·재생 각각 0/4였다. 최초 실행의 행동 시계 오류는 무효로 보존하고 수정한 새 20회만 집계했다. 이번 결과는 단일 조건의 학습 가능성을 유지하지만 피드백 학습이나 미사용 조건의 개선을 입증하지 않는다. 다음 변경 후보는 학습 보정 오차의 분포이며, 관측·보상·알고리즘을 한꺼번에 바꾸지 않는다. 이번 네 조건은 진단에 사용했으므로 이후 미사용 조건으로 다시 집계하지 않는다.

[단일·다중 보정 오차 PPO 비교](evidence/rj45-multibias-20261031/README.md)는 같은 train 파지에서 단일조건 학습과 네 조건 순환 학습을 각각 64 updates·8,192 transitions로 맞췄다. actor79·critic92, 초기 actor·critic·optimizer·RNG, 첫 anchor 79D 관측, 보상·행동 한도·판정과 PhysX seed를 고정했다. 미사용 8조건에서 single64 2/8, multi64 3/8, zero 2/8이었고, multi64의 짝지은 결과는 single64 대비 2승·1패·5무, zero 대비 1승·0패·7무였다. anchor에서는 세 방법이 모두 실패했다.

후속 다중 seed 후보 기준은 `multi64 >= single64 + 2`, `multi64 > zero`, `zero 성공→multi64 실패 <= 1`이었다. 첫 기준이 1건 차이로 미달해 후보가 되지 못했다. 한 학습 seed만 사용했으므로 학습 분포 변경의 효과·일반화·최종 정책은 입증하지 않았다. 이전 32-update 단일조건 PPO의 anchor 성공과 이번 64-update anchor 실패는 소스·설계·평가가 통제된 학습량 대조가 아니므로, update 증가의 효과로 해석하지 않는다. final 파지는 열지 않았다.

### G3. 근거에 맞는 개선 한 가지 선택

| 확인할 현상 | 단일 변경 후보 | 별도 검증 조건 |
| --- | --- | --- |
| 여러 보정 오차를 학습한 multi64가 single64보다 미사용 조건에서 1건 높았지만 후보 기준에 미달했다. | 초기 탐색 표준편차와 감쇠 방식 중 하나만 바꾸는 대조 | 초기화·학습 조건·보상·행동 한도·전이 예산·최종 checkpoint 선택을 고정하고, 비교값과 판정 기준을 실행 전에 등록한다. |
| 참조 제어기는 학습 정책 방문 상태에서 회복하지만 학습 정책은 실패한다. | 학습 정책 rollout의 상태에 참조 제어기 행동을 추가하는 DAgger형 데이터 보강 | 성공 경로·실패·참조 제어기 회복 불가 사례를 모두 보존하고 train 상태만 학습에 사용한다. |
| 정렬 이후에도 움직임이 남아 유지 조건이 깨진다. | 정렬·삽입 조건에서 활성화되는 안정화 보상 또는 보정 감쇠 | 보상과 감쇠를 한 번에 바꾸지 않는다. 기존 성공 조건은 유지한다. |
| 필요한 상태 차이가 현재 관측에서 구분되지 않는 증거가 있다. | 추정 상대 속도 또는 짧은 접촉·움직임 이력 | 현재 actor가 받는 추정값과 과거 값으로 계산한다. 정답 물체 속도나 평가기의 GT dwell을 학습 정책 입력에 넣지 않는다. |
| 학습 정책뿐 아니라 참조 제어기도 해당 상태에서 회복하지 못한다. | 참조 제어기 또는 제어 권한·과제 설계 검토 | 같은 데이터만 늘리는 경로는 중단한다. 환경 변경은 별도 버전과 새 기준선을 요구한다. |

보정 오차 분포 변경은 한 seed 비교를 마쳤으며 후속 다중 seed 후보 기준을 통과하지 못했다. 현재 목표는 원인을 확정하는 것이 아니라, 동결된 보상에서 탐색 명령의 크기와 감쇠가 엄격 판정 범위에 미치는 영향을 한 번에 한 요소씩 구분하는 것이다. 현재 dense reward의 횡오차 scale은 500 µm, 초기 병진 command 분포의 명목 표준편차는 150 µm, strict 횡오차 기준은 50 µm다. 150 µm는 실제 팁 오차 측정값이 아니며, 이 수치 차이만으로 탐색 설정을 실패 원인으로 확정하지 않는다. 다음 비교는 아직 실행하지 않았고 사전등록 검토 단계다.

이번 상수·재생 대조와 다중조건 비교에 사용한 보정 조건은 이후 미사용 평가 조건으로 재표시하지 않는다. 새 학습·개발 조건을 분리하고 무보정 기준과 조건별 성공·역전 실패를 대조한 뒤, 사전 기준을 통과한 경우에만 여러 학습 seed와 별도 파지 평가를 검토한다. 여러 환경의 병렬 학습을 사용할 때는 해당 소스와 환경 수에서 접촉 분리·부분 reset 검증을 먼저 통과해야 한다. 단일 환경의 이번 결과를 병렬 물리 검증으로 대체하지 않는다.

참조 제어기 리라벨링은 학습 정책이 행동하는 시각의 상태에 라벨을 붙이되, 참조 제어기 계산이 학습 정책 실행 상태를 바꾸지 않는 경로로 구현한다. 학습 정책 관측, 실행한 학습 정책 행동, 참조 제어기가 제안한 행동, 유효성·실패 이유와 시각을 분리한다. 복원한 물리 상태가 원래 접촉 상태와 동일하다고 가정하지 않는다.

이 live shadow-query 수집 경로는 현재 구현돼 있지 않다. 구현 후 상태 비변경, 시각 정렬, GT의 학습 정책 입력 누출 방지와 실제 물리 실행 검증을 통과해야 데이터 수집에 사용한다.

이전 행동을 0으로 만든 오프라인 시험은 분포 밖 입력일 수 있다. 그 결과나 국소 Jacobian만으로 shortcut 또는 로봇 불안정을 확정하지 않는다.

[전체 train 시연 대조](evidence/rj45-teacher-forced-baselines-20261030/README.md)에서는 기존 BC가 전체 평균 행동보다 낮은 MSE를 보였지만 직전 참조 제어기 행동 복사와의 차이는 작았다. 단일 조건의 평균 행동 진단을 전체 BC가 상태를 사용하지 않는다는 주장으로 확대하지 않는다. 참조 제어기가 만든 이전 행동과 학습 정책 실행 뒤의 이전 행동은 구분하고, 학습 정책 방문 상태에서의 참조 제어기 리라벨링과 폐루프 검증을 다음 데이터 비교의 근거로 삼는다. 이 분석도 실패 원인의 인과 증명은 아니다.

### G4. 강화학습의 추가 기여 비교

| 군 | 출발점과 학습 | 답할 질문 |
| --- | --- | --- |
| 기준 제어 | 학습 보정 0 | 현재 제어의 성공·안전·시간 기준은 무엇인가? |
| BC-only | 고정한 참조 제어기 데이터로 학습한 actor | 시연 학습만의 효과는 무엇인가? |
| PPO-only | 기존과 같은 잔차 초기화에서 PPO | 시연 없이 online 학습한 결과는 무엇인가? |
| BC→PPO | BC-only와 같은 actor checkpoint에서 PPO | PPO를 추가한 이득이 있는가? |

- 모든 군의 물리·supervisor·관측·행동·평가 조건을 맞춘다. 비교하려는 한 요소만 바꾼다.
- PPO 두 군은 환경 전이 수와 checkpoint 선택 규칙을 맞춘다. 참조 제어기 시뮬레이션과 BC의 추가 비용은 별도 보고한다.
- 같은 seed의 PPO 두 군은 초기화 전 actor·critic·탐색분포·optimizer와 Python·NumPy·Torch CPU·해당 CUDA 장치 RNG fingerprint가 같아야 한다. 초기화 후에는 actor만 달라지고 critic·탐색분포·optimizer·RNG가 같아야 한다. 실행 기록이 이 조건을 확인하지 못하면 paired 비교를 시작하지 않는다.
- 200 update가 수렴을 보장한다고 가정하지 않는다. pilot은 train 파지·train 보정 조건만 사용하는 탐색으로 두고, 그 결과와 모델을 본실험 결과에 합산하거나 본실험 checkpoint로 이어 쓰지 않는다. pilot의 처리량·학습 곡선으로 본실험의 전이 예산과 마지막 판정 checkpoint를 정한다.
- 본실험 전에 source/config/data 해시, seed 목록, horizon, 총 전이 수, 마지막 판정 checkpoint, 중간 진단 checkpoint, 평가 사례와 실제 bias 목록, 실행 순서, 집계 방법과 불확실성 계산을 별도 사전등록으로 고정한다. 중간 결과를 보고 예산·checkpoint·성공 기준을 바꾸지 않는다.
- 과거 개발 64조건과 G1의 촬영 사례는 가설 탐색에 사용한 자료다. 새 독립 검증처럼 재명명하지 않는다. 본실험은 사용하지 않은 고정 개발 보정 조건을 dev 파지에 배정하고 마지막 checkpoint로 한 번 승격 여부를 판단한다. 이 개발 판단도 최종 성능 주장을 대신하지 않는다.
- 최소 3개의 독립 학습 seed를 사용한다. 5개로 확대할 경우 그 수와 비용을 본실험 전에 고정한다. 결과를 보고 유리해질 때까지 seed를 추가하지 않는다.
- 새 개발 비교에서는 BC→PPO가 기준 제어·PPO-only·같은 BC-only 각각보다 평균 6/64 이상 높아야 승격한다. 기존 동결 실험에는 새 BC-only 조건을 소급 적용하지 않는다.
- 최종 평가에서 강화학습의 추가 기여 판정은 같은 BC-only 대비 성공률 차이가 평균 9.375%p 이상이고, 짝지은 95% 구간의 하한이 0보다 크며, 학습 seed 과반에서 차이가 양수일 때로 고정한다. 무효 episode 0과 금지 접촉 하중 0도 요구한다. 최종 표본 수가 64와 다르면 6건이 아니라 이 비율을 적용한다.
- 불확실성 구간은 학습 seed와 같은 파지 안의 짝지은 보정 사례를 재표집하는 계층 bootstrap으로 계산한다. 100,000회, 분석 seed `20261030`을 고정하고 실패 사례를 제외하지 않는다. 이 구간은 고정한 BC checkpoint와 최종 파지 표본에 조건부이며, 모든 파지·형상의 모집단으로 확대하지 않는다.
- 최종 차이가 0 이하이거나 안전·유효성 조건을 위반하면 개선 실패로 판정한다. 차이가 양수여도 최소 효과·구간·seed 조건 중 하나라도 만족하지 못하면 증거 불충분으로 판정하고 추가 기여를 확정하지 않는다. 낮은 최종 결과에 맞춰 같은 final 분할을 재학습에 사용하지 않는다.
- seed별 결과, 사례별 짝지은 차이와 불확실성, 무효·실패·접촉·시간을 함께 보고한다. 보상 합계나 BC MSE로 실제 성공률을 대체하지 않는다.
- 기존 동결 protocol JSON과 과거 결과는 수정하지 않는다. 새 실행의 설정·예산·seed·선택 규칙은 별도 사전등록으로 고정한다.

완료 조건: PPO의 이득이 BC 초기화 또는 시연 데이터의 이득과 구분돼야 한다. BC만 좋아지고 BC→PPO가 좋아지지 않으면 시연 학습의 결과로 기록하고 PPO 성공으로 표현하지 않는다. 시연을 쓰지 않는 경로에서는 비학습 제어 대비 PPO-only의 이득을 별도로 검증한다. SAC 대조는 관측·행동·보상·시연 접근 권한을 맞추고 환경 전이 수, gradient 갱신 수와 GPU 시간을 함께 보고한다. SAC에만 시연 replay를 추가한 결과를 알고리즘 하나의 효과로 표현하지 않는다. 새 환경과 새 비교군의 본실험 판정 조건은 해당 실행 전에 별도 고정한다.

방법론 비교형 포트폴리오를 구성할 때는 알고리즘 대조와 설계 요소 대조를 나눈다. 기본 PPO와 관측·보상을 개선한 PPO의 차이는 설계 변경의 효과이고, PPO와 SAC의 알고리즘 대조에서는 개선한 관측·행동·보상을 공통으로 고정한다. 정답 관측 oracle actor는 원인 진단용이므로 실행 정책들과 같은 성능 순위에 넣지 않는다. 같은 미사용 조건에서 성공·복구율, 실패 유형, 접촉 하중, 완료 시간, 학습 전이 수와 GPU 시간을 함께 비교한다. 차이가 없거나 불확실하면 그 결과를 보존하며, 모든 방법의 실행 오류나 0회 성공을 알고리즘의 일반적 우열로 해석하지 않는다.

actor뿐 아니라 critic이 받는 정보도 알고리즘 간에 맞춘다. privileged critic을 쓰는 진단 PPO와 critic 입력을 제한한 SAC를 알고리즘 하나의 효과로 비교하지 않는다. 첫 알고리즘 대조는 두 actor·critic 모두 같은 79D 입력으로 맞추는 구성을 우선 검토하고, critic 정보의 추가는 별도 대조로 둔다.

### G5. 미사용 조건과 지지팔 비교

후보와 checkpoint 선택을 끝낸 뒤 final 파지·보정 조건을 평가한다. 최종 결과를 보고 같은 분할에 맞춰 재학습하지 않는다. 현재 final 파지가 두 개인 검증은 그 작은 범위에 한정해 설명한다.

지지팔 제어 비교는 현재 도구의 실제 권한과 동일한 상대 Cartesian 보정 예산을 확인한 뒤 수행한다. 스크립트 지지팔 비교를 학습된 양팔 12D 정책으로 표현하지 않는다. 승인된 확장 단계에서는 새 task v2로 삽입 진행·미세 후퇴와 왼손의 제한된 평면 이동·작은 회전부터 정책 권한에 포함한다. 비학습 접촉 제어, 오른손 RL과 양팔 RL을 같은 상대 보정·하중 제한에서 비교한다. v1의 학습 가능성 진단이 통과했더라도 행동 범위가 바뀐 v2에서 참조 복구와 oracle 진단을 다시 수행한다. CAD 형상·안착 깊이·파지와 안정 유지·하중에 근거한 v2 판정을 실행 전에 고정하고 기존 strict 50 µm 결과는 별도로 보존한다. 기준 완화나 실패 조건의 사후 선택으로 개선을 만들지 않는다.

### G6. 포트폴리오 납품

최종 정책과 기준 제어의 동기 비교, 실제 정책 실패 약 두 편, 성공률·안전·시간·seed 편차 그래프와 재현 명령을 묶는다. 학습 전후의 동일 조건과 정책 해시를 영상·보고서에 연결한다. 실패 또는 불확실한 결과도 원본 근거에 보존한다. 독립 검토 후 로컬 커밋, 승인된 main 반영·push와 원격 SHA 대조를 완료한다.

## 로컬과 Brev의 역할

로컬은 기존 rollout·HDF5 분석, 작은 BC 회귀, 단위 계산, 그래프·문서에 사용한다. 현재 RTX 5050 Laptop 8GB와 드라이버 불일치·저장 여유 상태에서는 고정 Isaac 5.1 환경의 물리 실행 가능 여부를 확인하지 못했다.

실행 중인 Brev 인스턴스 한 대에서 물리 재현, 참조 제어기 리라벨링, 폐루프 진단과 PPO를 순서대로 수행한다. 기존 서버는 정지 상태로 보존하고 추가 서버에서 재개하는 구성을 사용자가 허용했다. GPU별로 독립 실행을 배치할 수 있지만 네 GPU를 정책 한 개의 분산 학습으로 사용했다고 표현하지 않는다. 실험을 마친 뒤 결과를 회수하고 인스턴스를 정지한다.

## 적용 근거

- [DAgger, Ross 외, AISTATS 2011](https://proceedings.mlr.press/v15/ross11a.html): 학습 정책이 방문한 상태에서 참조 제어기의 행동 라벨을 수집하는 근거. 현재 RJ45 실패 원인이라는 증명은 아니다.
- [DAPG, Rajeswaran 외, RSS 2018](https://www.roboticsproceedings.org/rss14/p49.html): 시연과 정책 최적화를 결합하는 근거. 이 프로젝트의 BC→PPO는 논문 전체 재현이 아니다.
- [IndustReal, RSS 2023](https://arxiv.org/abs/2305.17110): 접촉 조립의 보상·물리·커리큘럼을 분리해 검토하는 참고. 대응점 보상을 SDF 구현으로 표현하지 않는다.
- [ResiP](https://arxiv.org/html/2407.16677v4): 고정한 시연 정책에 매 제어 시점의 PPO 보정을 결합한 정밀 조립 사례다. 현재의 단일-step MLP와 논문의 chunked 시연 정책을 같은 구현으로 표현하지 않는다.
- [Fabrica](https://fabrica.csail.mit.edu/): 양팔 조립에서 계획과 접촉 구간 학습을 결합한 참고다. 논문의 계획·지각·실물 결과를 이 프로젝트의 성과로 사용하지 않는다.
- [Soft Actor-Critic](https://arxiv.org/abs/1812.05905): 경험 재사용을 사용하는 조건부 알고리즘 대조 후보이며, 알고리즘 교체만으로 관측·제어 문제를 해결한다고 가정하지 않는다.
